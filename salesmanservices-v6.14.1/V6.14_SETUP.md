# Salesman Services V6.14 — GitHub + Cloudflare setup

This package is prepared for GitHub/Cloudflare deployment. **No real secrets are included.**

## 1. Before GitHub

- Do not commit `.dev.vars`, `.env`, API keys, passwords, webhook URLs or encryption keys.
- `.gitignore` already blocks local secret files.
- `wrangler.jsonc` declares the five Production secrets the Worker expects.

## 2. Cloudflare Production secrets

Open **Workers & Pages → holy-tooth-c11a → Settings → Variables and Secrets → Production → Add**.

For each of these choose **Type = Secret**, not Variable:

| Name | What to enter |
|---|---|
| `RESEND_API_KEY` | Your Resend API key (prefer a Sending Access key restricted to your sending domain) |
| `DELIVERY_FROM_EMAIL` | A From address on a verified Resend domain, e.g. `Salesman Services <delivery@salesmanservices.com>` |
| `ADMIN_PASSWORD` | A new strong admin password |
| `DISCORD_ORDER_WEBHOOK` | Your new Discord webhook URL |
| `VAULT_ENCRYPTION_KEY` | Your new vault encryption key |

After adding/changing them, click **Deploy**. Cloudflare documents that secrets are encrypted and hidden after they are saved; sensitive values should not be stored as plaintext variables.

## 3. Resend

1. In Resend, add/verify `salesmanservices.com` (or the exact domain you will use in the From address).
2. Complete the DNS verification records Resend shows.
3. Create a Production API key. A **Sending Access** key restricted to the verified domain is preferred.
4. Copy the key once and paste it into the Cloudflare `RESEND_API_KEY` Secret.
5. Set `DELIVERY_FROM_EMAIL` to an address on the verified domain.

Never put the Resend key in GitHub.

## 4. GitHub

Upload the **contents of this folder**, not the ZIP file itself, to your repository root. GitHub should show `package.json`, `wrangler.jsonc`, `worker/`, `public/`, `app/`, etc.

Recommended first commit message:

`V6.14 — professional checkout, mobile refinement, automatic delivery setup`

## 5. Cloudflare Pages/Workers Builds

Use the repository/branch that your current Worker deployment already watches. The existing build command is `npm run build` and the Worker deploy command is `wrangler deploy`. Keep the existing KV namespace binding `SALESMAN_DATA`.

## 6. After deployment

Test with a small controlled order before announcing the shop as fully automatic:

1. Open an eligible account.
2. Enter an email you control.
3. Create the order.
4. Confirm the account is reserved.
5. Send the exact BTC/LTC amount shown.
6. Watch the live order status.
7. Confirm the order becomes paid.
8. Confirm the email arrives with the account details.
9. Confirm the account changes to sold.
10. Check Cloudflare Worker logs and Resend events if anything fails.

If Resend temporarily fails after payment, V6.14 keeps the order paid and retries delivery through the scheduled Worker checks.
